## Workstation rename and missing Open WebUI models

**Symptom:** the WebUI loaded but its Ollama models were missing after workstation/network changes.

**Isolation:** a request from the WebUI container to the workstation's current logical hostname reached Ollama's model-list endpoint. The persisted WebUI Ollama base URL still used an unreachable previous numeric endpoint. Container environment settings alone did not establish the saved application setting.

**Resolution:** back up the WebUI database, then change only its saved Ollama base URL through the application's API to the current private endpoint. No restart, database reset or chat deletion was needed.

**Validation:** six Ollama models and custom assistants returned. All 99 chats and the user account matched the pre-change backup. The disabled OpenAI connection had no configured key and was not an alternate local inference path; enabling it was not the fix.

**Prevention:** after a host rename or address change, test name resolution and the model endpoint from inside the consuming container, inspect persisted connection settings, and verify models plus retained user data. Keep actual backend addresses and database backups private.

## Sentinel backup authentication

**Symptom:** Sentinel could not complete its backup transfer to Basecamp.

**Cause and correction:** the receiver's authorized-key line lacked its key-type prefix. Correcting the line and pinning the destination host key restored authentication. A dedicated forced-command receiver restricts the backup account; destination drive identity, free space, archive size and checksum are checked.

**Validation:** a downloaded backup matched its checksum; five SQLite databases, the Pi-hole export archive and Uptime Kuma data passed staged checks. No production database was overwritten. Retention is three local and thirty successful destination snapshots.

## Sentinel independence and container firewall path

A temporary, automatically reverting firewall test isolated Sentinel from Basecamp/core-services. Pi-hole, uncached DNS, local monitoring, SSH, Tailscale and emergency status remained available. Backup failure was surfaced during isolation and a backup succeeded after connectivity returned. This tested a network dependency failure, not loss of mains power.

A separate firewall issue allowed Kuma's container to resolve DNS but blocked its access to Sentinel's Pi-hole web interface. A narrowly scoped rule corrected that path, followed by HTTP and monitor checks. Existing Docker and Tailscale rules were preserved. Eight Sentinel monitors were healthy at completion; temporary test rules were removed.
